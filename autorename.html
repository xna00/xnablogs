提取 .docx 文件标题并自动设置为文件名

Github repo

.docx 文件简介

.docx 文件是 Office Open XML（简称 OOXML）文件格式的一种，本质上是一个包含多个 XML 文件的压缩包。除 .docx 外，.pptx 和 .xlsx 也属于 OOXML 文件格式家族。

可以通过 OOXML Explorer 工具查看 OOXML 文件的内部结构，直观了解其组成方式。

实现思路

解压缩 .docx 文件后，可以看到其中包含 word/document.xml 和 word/styles.xml 等核心文件。其中，document.xml 包含文档的实际内容，而 styles.xml 则存储预定义的样式信息。文档内容中可能包含内联样式定义，也可能通过 styleId 属性引用 styles.xml 中定义的样式。

本工具的核心思路是：识别文档头部字号较大的文本内容，将其判定为文档标题，然后使用该标题自动重命名原文件。

适配 QuickJS

若使用 Node.js 将代码打包成可执行文件，最终文件大小约为 30MB；而通过 QuickJS 编译后，可执行文件体积仅为 1MB。

适配过程中，主要需要重新实现读写文件和解压缩相关的 API。

读写文件

const readFileSync = (path: string) => {
  const f = std.open(path, "rb+");
  const ret: number[] = [];
  while (true) {
    const b = f.getByte();
    if (b === -1) {
      break;
    }
    ret.push(b);
  }
  f.close();
  return new Uint8Array(ret);
};

const bufferToString = (buf: Uint8Array) => {
  const f = std.tmpfile();
  f.write(buf.buffer, 0, buf.length);
  f.flush();
  f.seek(0, 0);
  const ret = f.readAsString();
  f.close();
  return ret;

问题记录与解决方案

经过适配后，代码在 macOS 环境下运行正常，但在 Windows 平台测试时遇到了以下问题：

编译可执行文件

在 Windows 环境中，qjsc 无法像在 Unix 系统那样直接将 JS 文件编译为 C 代码后调用 GCC 生成可执行文件，而只能生成包含字节码的 C 文件。

解决方案：使用 MinGW 进行交叉编译，或在 Windows 系统中通过 MSYS2 环境进行编译。此外，由于代码依赖 POSIX threads，需要附带 libpthread.dll 库文件，也可选择静态链接该库。另一种方案是关闭 USE_WORKER 和 CONFIG_ATOMICS 选项，从而避免对线程库的依赖。

中文乱码问题

在 Windows 平台上，直接打印到控制台的中文内容会出现乱码，但将输出重定向到文件时则正常显示。这是因为代码输出使用的是 UTF-8 编码，而 Windows 控制台默认采用 GBK 编码。

解决方案：执行 chcp 65001 命令将控制台切换为 UTF-8 编码模式，或在代码中调用 SetConsoleOutputCP(CP_UTF8) API 进行设置。

此外，文件路径重命名时也会出现乱码问题，这是因为调用 C 语言的 rename 函数时，底层 Win32 API 会以 ANSI 编码解析 UTF-8 字节序列。

解决方案：调用 setlocale(LC_ALL, ".UTF8") 应该解决这一问题。

文件读取不完整

使用 getByte 或 fread 函数读取文件时，经常出现读取到部分内容就提前结束的情况。

问题原因：打开文件时错误地使用了文本模式标志 r。在文本模式下，当读取到值为 0x1a（对应 Ctrl+Z 字符）的字节时，系统会将其视为文件结束符，导致文件读取提前终止。

解决方案：应使用二进制模式标志 rb 打开文件，确保完整读取所有字节内容。

std.tmpfile 调用失败

在 Windows 环境中，调用 std.tmpfile 函数时频繁失败。

问题原因：MSVCRT（Microsoft Visual C++ Runtime）对 tmpfile 函数的实现存在缺陷。

解决方案：使用 UCRT（Universal C Runtime）替代 MSVCRT 即可解决此问题。

注册表设置

可以通过修改 Windows 注册表，将本工具添加到右键菜单中：

  1. 按下 Win + R 组合键，输入 regedit 并按回车，打开注册表编辑器

  2. 导航至以下路径：HKEY_CLASSES_ROOT\.docx

  3. 查看右侧窗口的「(默认)」值，记录其数据内容（通常为 Word.Document.12 或类似值）

  4. 导航至 HKEY_CLASSES_ROOT\[上一步记录的值]（例如 HKEY_CLASSES_ROOT\Word.Document.12）

  5. 展开该节点，依次进入 shell 子项

  6. 在 shell 上右键，选择「新建」→「项」，命名为你希望在右键菜单中显示的文本（例如「自动重命名」）

  7. 在刚创建的项上右键，选择「新建」→「项」，命名为 command

  8. 双击 command 项的「(默认)」值，设置其数据为工具的执行命令，例如：

    C:\Users\xxx\autorename.exe "%1"

    其中，%1 表示当前选中的 .docx 文件路径
