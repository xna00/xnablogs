Github repo

docx 文件简介

docx 文件属于 Office Open XML 文件的一种，本质上是一个压缩包，包含了一堆 xml 文件。pptx、xlsx 也属于 OOXML 。

可以在 OOXML Explorer 中查看 OOXML 文件的内部结构。

实现思路

解压缩之后，会有 word/document.xml 和 word/styles.xml。第一个就是文档的内容，第二个是预定义的样式。文档中有内联样式，也可能设置一个styleId指向styles.xml中的样式。

通过查找文档头部字号较大的内容，就能读取文档标题，用标题重命名文件即可。

适配 QuickJS

用 Node.js 打包成 exe 文件，大小估计在 30M 左右。用 QuickJS 编译成 exe，只有 1M。

需要适配的主要是读写文件和解压缩相关 API。

读写文件

const readFileSync = (path: string) => {
  const f = std.open(path, "rb+");
  const ret: number[] = [];
  while (true) {
    const b = f.getByte();
    if (b === -1) {
      break;
    }
    ret.push(b);
  }
  f.close();
  return new Uint8Array(ret);
};

const renameSync = (oldPath: string, newPath: string) => {

  const f = std.tmpfile();
  f.write(buf.buffer, 0, buf.length);
  f.flush();
  f.seek(0, 0);

问题记录

理论上，这样适配完之后就能用了，在 Mac 上测试也确实没问题，但是在 Windows 上测试遇到很多问题。

编译 exe

qjsc在Windows上不能像在Unix上一样，把js文件编译成c文件之后，调用gcc编译可执行文件，只能编译出包含字节码的c文件。

要使用mingw交叉编译，或在Windows上在msys2环境中编译。

由于依赖了POSIX threads，要附带 libpthread.dll，可以把它静态链接进去。也可以关掉 USE_WORKER 和 CONFIG_ATOMICS，就不依赖 threads 了。

中文乱码

在 Windows上，打印到控制台的中文内容会出现乱码，而把打印内容重定向到文件中就不会。因为打印是用的uft8字节序列，Windows默认用的GBK编码。执行chcp 65001把控制台切到UTF-8，或者调用SetConsoleOutputCP(CP_UTF8)。

在对文件重命名时，文件路径也会出现乱码。调用 c rename时，底层 win32 API 会以 ANSI 解码 uft8 字节序列。

经测试setlocale(LC_ALL, \".UTF8\")可以解决乱码问题。

文件读取不完整

用getByte或fread读取文件时，总是读取一部分就结束了。因为打开文件时用错了 flag，用r表示以文本的形式打开，0x1a等于crtl+z，所以读取到这个字节时就提前结束了。应该使用 rb flag。

调用std.tmpfile失败

因为 msvcrt 对 tmpfile 的实现有问题 参考，使用 ucrt 即可。

设置注册表

按下Win + R，输入regedit打开注册表编辑器

导航到以下路径：HKEY_CLASSES_ROOT\.docx

查看右侧窗口的(默认)值，记下其数据（通常是Word.Document.12或类似值）

导航到HKEY_CLASSES_ROOT\[上一步的值]（例如HKEY_CLASSES_ROOT\Word.document.12） 展开该节点，依次进入shell子项

在shell上右键，选择新建 -> 项，命名为你想要在右键菜单中显示的文字（例如我的操作）

在刚创建的项上右键，选择新建 -> 项，命名为command

双击command项的(默认)值，设置其数据为你要执行的命令，例如：

C:\Users\xxx\autorename.exe "%1"

其中%1表示当前选中的 docx 文件路径
