strongSwan 配置记录

目前家用宽带和移动网络都已经可用 IPv6 公网地址，可以搭建一个 VPN 网关，使所有手机流量经网关中转。

假设 VPN 网关的 IP 为 192.168.11.120，路由器的 IP 为 192.168.11.1。

Android builtin VPN

IKEv2: Internet Key Exchange Version 2 密钥交换

PSK: Pre Shared Key 预共享密钥

IPSec 标识符: 一个 ID

strongSwan 简介

strongSwan 是一个完整的 IPsec 解决方案。

Remote Access / Roadwarrior Clients

主机连接 VPN 网关

Remote Hosts / Host-to-Host

主机连接主机

Remote Sites / Site-to-Site

网关连接网关，使得两个网关及背后的设备在同一个子网中，可以直接相互访问。

我的目标场景就是 Roadwarrior Clients

安装

sudo apt install strongswan
sudo apt install libstrongswan-extra-plugins

配置

sudo nvim /etc/swanctl/swanctl.conf

connections {
  rw {
    version = 2
    # For windows builtin vpn client
    # proposals=aes256-sha256-modp2048,aes256-sha1-modp1024
    local {
      auth = psk
      # Sep 04 21:54:31 debian charon-systemd[712]: looking for peer configs matching 192.168.11.120[192.168.11.120]...192.168.11.171[abc]
      id = %any
    }
    remote {
      auth = psk
      # Sep 04 21:54:31 debian charon-systemd[712]: looking for peer configs matching 192.168.11.120[192.168.11.120]...192.168.11.171[abc]
      # id 对应 Android VPN 的 "IPSec 标识符"
      id = %any
    }
    children {
      android {
        # 当 VPN 网关收到一个数据包时，用remote_ts匹配源地址，用local_ts匹配目的地址
        # 理论上，VPN 网关会和客户端协商，网关的 local_ts 和 客户端的 remote_ts 取交集。
        # CHECK: 但 Android builtin VPN 不支持协商，只能写死。是这样吗？？?
        local_ts = 0.0.0.0/0
        remote_ts = 10.10.30.0/24
          updown = /usr/lib/ipsec/_updown iptables
          hostaccess = yes
        mode = tunnel
      }
    }
    pools = vpn-pool
  }
}

pools {
  vpn-pool {
    # 分配给客户端的 IP 范围
    addrs = 10.10.30.0/24
    # 给客户端指定 DNS 服务器
    dns = 192.168.11.1
  }
}

secrets {
  # PSK 密钥
  # ike-<suffix> 这个后缀好像没用？

  # this PSK will be used for any identity if there is no better match
  # because there is no "id" field in this section
  ike-android {
    secret = share_psk  # 密钥（无特殊字符可省略引号）
  }
}

# Include config snippets
include conf.d/*.conf

sudo swanctl --load-all

这样配置好之后，手机就可以连接上了。

连上之后，会发现无法上网，ping 192.168.11.120没问题，但是ping 192.168.11.1不行。

在 VPN 网关上，用sudo tcpdump dst port 53抓包，发现转发的数据包目的地址是正确的，而源地址是虚拟 IP 10.10.30.1。这说明数据包被转发出去了，但是目标IP返回的数据包回不来，因为没有到 10.10.30.1 的路由。

这时要设置 SNAT，参考 strongSwan 转发文档

至此，手机连上VPN就能正常上网了，还能直接和 192.168.11.0/24 的设备通信。
